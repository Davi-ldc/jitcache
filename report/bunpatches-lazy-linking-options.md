# bunpatches.md: the fork's lazy linking and heuristics options have no section

Doc: `skills/reference/knowledge/common/bunpatches.md`; a new section, for example after "Startup".

## What changed

The fork now carries a family of options that upstream `WebKit/WebKit` at `dbdca7545d` does not have (checked with `git grep` on `Source/JavaScriptCore/runtime/OptionsList.h` at both revisions). Most change when per-`CodeBlock` state is created. All are on by default except where noted. Two, `useRunOnceCodeRelease` (`FOR_EACH_JSC_CODEBLOCK_AGING_OPTION`) and `usePrelinkedModuleInfo` (`FOR_EACH_JSC_BYTECODE_CACHE_DECODER_OPTION`), exist only under `USE(BUN_JSC_ADDITIONS)`; the rest are ordinary options:

| option | what it defers or changes | report |
|---|---|---|
| `useLazyFunctionExecutables` | a `CodeBlock`'s nested `FunctionExecutable`s, created on first `new_func*` or before the first compilation (`prepareLazyStateForConcurrentCompilation`) | basics-lazy-linking |
| `useLazyModuleFunctionDeclarations` | a module's function declarations, instantiated into their environment slot on first read (`LazyClosureVar`) | inlinecaches-lazy-closure-var |
| `useLazyLLIntCallLinkInfos` | a call site's `CallLinkInfo` and `this` profile, in a `CallSiteData` the site gets at its second execution | inlinecaches-lazy-call-site-data |
| `useLazyValueProfilePredictions`, `thresholdForValueProfilePredictions` (40) | a metadata table's predictions array, and the GC drains of cold interpreted code | profiles-value-profile-buckets-and-predictions, profiles-samples-kept-below-threshold |
| `useLazyCatchLiveness` | `op_catch` buffers, created when the function first crosses its DFG threshold | profiles-lazy-catch-buffers |
| `useRunOnceCodeRelease` | releases the code of top-level bodies that ran once | basics-run-once-release |
| `useSharedRegExpLiteralObjects` | one `RegExpObject` per literal site when unobservable (`new_reg_exp_shared`) | baseline-compiler-new-embedded-references |
| `useBytecodeOptimizer` (off) | the whole-function bytecode optimizer on all generated bytecode; cache generation runs it under `OptimizeBytecode::Yes` | bunpatches-bytecode-cache-1-4-3 |
| `usePrelinkedModuleInfo` | module records answered from a prelinked graph's tables | bunpatches-bytecode-cache-1-4-3 |
| `startupJITDeferralScale` (1) | multiplies the LLInt→baseline and baseline→DFG thresholds during a VM's startup window | basics-startup-deferral-scale |
| `weakReferenceJettisonReoptimizationLimit` (4) | lets dead-weak-reference jettisons count toward the reoptimization back-off | basics-weak-reference-jettison-backoff |

The UCB's value and array copies are also allocated only at the first baseline compilation (`ensureValueAndArrayProfiles`), with no option (report basics-ucb-profiles-allocated-at-baseline).

## Proposed text

New section:

> ## Lazy linking
>
> A second line of work makes linking cheap for code that runs once or never: a `CodeBlock` creates its nested `FunctionExecutable`s on first use (`useLazyFunctionExecutables`), a module its function declarations on first read (`useLazyModuleFunctionDeclarations`), a call site its `CallLinkInfo` and `this` profile at its second execution (`useLazyLLIntCallLinkInfos`), a metadata table its value predictions when one has something to record (`useLazyValueProfilePredictions`), and an `op_catch` its buffer at the function's first DFG threshold (`useLazyCatchLiveness`). The `UnlinkedCodeBlock`'s value and array copies wait for the first baseline compilation, and top-level code that ran once releases its code (`useRunOnceCodeRelease`). On the heuristics side, a VM can defer tier-up during startup (`startupJITDeferralScale`, also set by the embedder) and dead-weak-reference jettisons count toward the back-off (`weakReferenceJettisonReoptimizationLimit`). These are engine options, on by default, so they apply to every embedder of the fork; only `useRunOnceCodeRelease` among them needs `USE(BUN_JSC_ADDITIONS)`. The mechanisms are in [basics.md](../../basics.md), [profiles.md](./profiles.md) and [inlinecaches.md](./inlinecaches.md).
