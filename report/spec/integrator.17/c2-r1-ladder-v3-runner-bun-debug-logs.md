Requirement. SPEC-integrator.harness.md section 7.7, "Bun-hosted runs" (the section has no rule ID): "The environment carries `BUN_DESTRUCT_VM_ON_EXIT=1` in place of `--destroy-vm`, `WebKitMallocForceEnabled=1` when the calibration of section 7.3 chose it, and `BUN_JSC_useConcurrentJIT=0` under the same rule as section 7.4. Every other run option `--<option>=<value>` is passed as `BUN_JSC_<option>=<value>`", and "The oracle run is `bun <script>` without the JITCache flags, and compares standard output". Section 7.6 compares that output "byte for byte, which carries the results, exceptions and stack traces the script prints".

Why the code cannot meet it as written. Every Bun twins build is a debug Bun, and a debug Bun writes the logs of its visible scopes ([sys], [cachefs], [loop], [subprocess], [filesink] and others) to standard output. So stdout carries more than the script prints. These lines differ between any two processes, JITCache on or off: they name pids, socket inodes, poll addresses and the process's own output file (run<i>.stdout against oracle<j>.stdout), and they log event-loop work in varying order. JITCache's directory pins and producer lock also shift descriptor numbers by a constant. A sequence's first run alone logs the one-time `bun build --compile` and Bun's transpiler-cache miss. Taken literally, the list leaves the logs on, and all 12 Bun-hosted scripts fail section 7.6 at line 1.

What the code does instead. The runner reads section 7.7's list as the variables that configure the engine for the run, as it already does when it adds `ASAN_OPTIONS` and `LSAN_OPTIONS` for section 7.5's leak judgment, which no section names. `bunInvocation` adds `BUN_DEBUG_QUIET_LOGS=1` to the environment of every Bun process it starts, runs and oracle runs alike, as Bun's own test harness does. The apps a script starts through `buildApp` and `runApp` inherit it, a release Bun ignores it, and a `BUN_DEBUG_<tag>` or `BUN_DEBUG_ALL` the caller exports still takes precedence. Stdout then carries only what section 7.6 says it carries, and the byte-for-byte comparison is unchanged. jsc processes, the pin comparison, calibration, maintenance and checkers do not get the variable. Nothing is asked of other tasks. The SPEC only has to add `BUN_DEBUG_QUIET_LOGS=1` to section 7.7's environment list.

Evidence. `init_scoped_debug_writer_at_startup` in `~/bun/src/bun_core/output.rs` gives the scoped writer `SOURCE.raw_stream` (stdout) unless `BUN_DEBUG` names a file; `ScopedLogger::evaluate_is_visible` in the same file checks `BUN_DEBUG_<tag>`, then `BUN_DEBUG_ALL`, then `BUN_DEBUG_QUIET_LOGS`, which ORs into `really_disable`. `writeStderrLine` in `~/bun/src/jsc/bindings/JITCacheHost.cpp` writes the final status and warning lines to stderr, where `checkStatuses` reads them. `bunInvocation` in `Tools/Scripts/run-jitcache-tests` builds the environment of both the run loop and `runOracle`. `buildApp` and `runApp` in `JSTests/jitcache/ucb/resources/ucb-bun.js` pass `{...process.env}` to the processes they start. In the kept failure (ladder-c2-r1, `ucb_borrowed-bytecode.js`), run0, run1 and oracle0 print the same three script lines once the log lines are removed, and the quiet rerun (`diag-bun-quiet-a1.log`) leaves no log line in any stdout; the 4 scripts that still fail there already exited 1 in the original V3 run and are separate items.
