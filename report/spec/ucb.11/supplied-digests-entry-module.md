Requirement. SPEC-ucb.md section 13.3, `supplied-digests.js`: "a `--compile --bytecode` executable run as producer and then as consumer, with strict on: no source digest is computed while its modules and the internal modules it loads are decoded (`sourceDigests` unchanged, `suppliedSourceDigests` counts them)".

Why the code cannot meet it as written. No read of the statistics comes before the app's entry module is decoded, so for that module nothing can show `sourceDigests` unchanged. The first read is the app's first statement, and by then the counter also holds digests computed for roots that are not the app's modules. Bun calls `start` before it creates the VM's global object, and the global object's setup creates some of Bun's own JS builtins (`GlobalObject::addBuiltinGlobals`). Each of those builtins is a range of one provider that holds them all (`createBuiltinsSourceProvider`), so none spans its provider, and section 3.5 computes its root digest from its text (form 3). The counter is therefore nonzero at the first read whether the entry module's digest was supplied or not.

What the code does instead. `JSTests/jitcache/ucb/resources/supplied-digests-app.js` checks the claim over the one load it can bracket: a window around the load of the embedded module and of `node:querystring`. Decoded from bytecode, that window must leave `sourceDigests` unchanged while `suppliedSourceDigests` grows by at least two, one for each. For the entry module, the start of the app keeps the checks that do not depend on the counter: without `--bytecode` the Consumer's entry module has imported, and with strict on that import verified the digest its key rests on. Nothing is asked of other tasks.

Evidence.
- `Zig__GlobalObject__create` (`~/bun/src/jsc/bindings/ZigGlobalObject.cpp`), which calls `Bun::JITCacheHost::configureVM` before creating the global object, and `GlobalObject::addBuiltinGlobals` there, which `finishCreation` calls and which creates builtins such as `fifoCreateFIFOCodeGenerator(vm)` and `commonJSOverridableRequireCodeGenerator(vm)`.
- `createBuiltinsSourceProvider` and the executable getters `bundle-functions.ts` generates (`~/bun/src/codegen/bundle-functions.ts`), which create each builtin through `JSC::createBuiltinExecutable` from a range of that provider.
- `rootSourceDigest` (`jitcache/UCBKeys.cpp`), whose form 2 needs a root that spans its provider.
