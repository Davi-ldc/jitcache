# bunpatches.md: the bytecode cache section predates the current payload format

Doc: `skills/reference/knowledge/common/bunpatches.md`, section "Startup".

## Passage

> The structural change is `useBorrowedBytecodeFromCache`: an `InstructionStream` decoded from a payload the embedder marked as persistent (`CachePayload::setIsPersistent`) points to the mapped bytes instead of copying them, `InstructionStream` gained a `Borrow` mode and reads everything through `span`, and the `UnlinkedCodeBlock` counts the borrowed bytes toward GC pacing as if it had generated the bytecode; the copy savings do not reduce that count. Without an embedder marking a payload as persistent, none of this happens.

## What changed

- `OptionsList.h` has no `useBorrowedBytecodeFromCache`, `verifyBytecodeCacheChecksums` or `useLeanBytecodeCacheDecoder`; `CachedTypes.cpp` has no per-record checksum (`bytecodeCacheRecordChecksum`, `crc32c`). Borrowing is unconditional for a persistent payload: `CachedCodeBlock::instructions` builds the stream with `JSInstructionStream::Borrow` whenever `Decoder::canBorrowPayload()`. `UnlinkedCodeBlock::visitChildrenImpl` still reports `m_instructions->sizeInBytes()`, so GC pacing counts borrowed bytes. `estimatedSize`, the heap-snapshot size, counts only `ownedSizeInBytes()`, which is 0 for a borrowed stream.
- Decoding defers more into the payload: a decoded UFE leaves members in it until asked (`UnlinkedFunctionExecutable::materializeDeferredMembersSlow`, scalars packed by `CachedFunctionExecutable::packScalars`), a UCB's expression info is decoded on first use (`expressionInfoSlow`), and a module's heap-allocated function declarations can stay in it (`UnlinkedCodeBlock::functionDeclSlow`; `Decoder::canDeferIntoPayload`).
- Persistent payloads are registered per VM (`PersistentBytecodePayloads`, `Decoder::RecoverableCode`), so decoded code can be dropped and decoded again: `UnlinkedFunctionExecutable::returnCodeToCache` and `ModuleProgramExecutable::releaseUnlinkedCodeIfRecoverable` (basics.md has the report).
- `bun build --compile --bytecode` now generates optimized bytecode (`OptimizeBytecode::Yes` to `recursivelyGenerate*`, which runs `BytecodeOptimizer`), unless given `--no-optimize-bytecode`. The engine option `useBytecodeOptimizer` (off) would run it on all generated bytecode. Such bytecode can carry resolve types only linking understands (inlinecaches.md has the report).
- With a payload order file, the modules of a link are encoded into one payload, laid out by how a recorded run used them (`BytecodeLinkEncoder`, regions `BytecodeLinkRegions`). A run records that order with `BytecodeOrderRecorder` (`PersistentBytecodePayloads::enableOrderRecording`); Bun writes the file at exit (`bytecode_order_recorder::write_at_exit`) and keeps unlinked code alive while recording (`VM::keepUnlinkedCodeUntil`, which `keepsUnlinkedCode` reads to suspend code dropping).
- A standalone executable can carry a prelinked module graph (`PrelinkedModuleGraph`, "PLMG" version 2), whose records resolve imports and exports from flat tables instead of by-name maps (`AbstractModuleRecord::isPrelinked`, option `usePrelinkedModuleInfo`, default on).

## Proposed text

Replace the passage with:

> Decoding works on the payload in place. A payload the embedder marks as persistent (`CachePayload::setIsPersistent`) is borrowed, not copied: the `InstructionStream` points to the mapped bytes (`Borrow` mode), GC pacing still counts them, and the VM registers the payload (`PersistentBytecodePayloads`) so that decoded code can be dropped and decoded again from it. What is not needed yet stays in the payload until first use: a UFE's cold members, a block's expression info, a module's function declarations. There are no per-record checksums. `bun build --compile --bytecode` generates optimized bytecode (`OptimizeBytecode::Yes`, the `BytecodeOptimizer`) unless given `--no-optimize-bytecode`, can lay every module of the link out in one payload in the order a recorded run used it (`BytecodeLinkEncoder`, `BytecodeOrderRecorder`), and can ship a prelinked module graph whose records resolve imports from tables (`PrelinkedModuleGraph`, `usePrelinkedModuleInfo`). Without an embedder marking a payload as persistent, none of the borrowing and re-decoding happens.
